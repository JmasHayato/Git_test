# 1.1　基本設計

## 1.1.1 プロジェクト基本情報

本システムは、ディップ様の申込・契約管理システム（ISHIN）として、Amazon Web Services（以下AWS）上に構築するものとする。

### 基本情報

| 項目名 | 値 | 備考 |
|--------|-----|------|
| 顧客名 | ディップ | 正式顧客名称 |
| 顧客名（英名） | dip | システムを識別する名称 |
| プロジェクト名 | dip | システムを識別する名称 |
| システム名 | 申込・契約管理システム | 正式システム名称 |
| システム名（英名） | ISHIN | リソース名などで利用 |
| 本番環境識別子 | prd | 環境を識別するタグ |
| ステージング環境識別子 | stg | 検証環境を識別するタグ |
| DR環境識別子 | prd-dr, stg-dr | 災害対策環境識別子 |
| 共通環境識別子 | com | アカウント共通リソース識別子 |


### リージョン・AZ設定

| 項目名 | 値 | 備考 |
|--------|-----|------|
| プライマリリージョン | 東京リージョン (ap-northeast-1) | メインの稼働リージョン |
| DRリージョン | 大阪リージョン (ap-northeast-3) | 災害対策リージョン |
| 使用AZ（東京） | AZ-A, AZ-C, AZ-D | Multi-AZ構成 |
| 使用AZ（大阪） | AZ-A, AZ-B, AZ-C | DR環境のMulti-AZ構成 |

## 1.1.2 利用サービス(AWS、その他)

本システムは、Amazon Web Services （以下AWS）上に構築するものとする。  
本システムのインフラ環境は、AWSの以下のメニュー及びその他サービスを利用する。

|サービス|メニュー項目|サービス|詳細|説明|
|--|---|---|---|---|
|AWS|コンピューティング|Fargate|ECS Fargate|APIサーバー、Bastionサーバーのコンテナ実行環境として利用|
|||Lambda|関数実行|バッチ処理の実行環境として利用|
||データベース|Aurora|MySQL互換|RDBMSとして利用|
|||ElastiCache|Redis OSS|キャッシュサーバーとして利用|
||ストレージ|S3|オブジェクトストレージ|バックアップデータ、各種ログ、業務データを保管するために利用|
|||ECR|コンテナレジストリ|FargateのDockerイメージ保管と取得に利用|
||ネットワーク|VPC||プライベートネットワーク空間作成のためVPCを利用|
|||ALB|Application Load Balancer|APIサーバーへの負荷分散に利用|
|||CloudFront|CDN|S3上のコンテンツ配信の高速化、API高速化のため利用|
|||Route 53|DNS|ドメイン管理サービス|
|||Shield|Standard|ネットワークおよびトランスポートレイヤーの DDoS 攻撃を防御|
||セキュリティ|Security Group/ACL||IP/Portによる通信制限のため利用|
|||WAF||SQLインジェクション、XSS、Bot攻撃対策のために利用|
|||Secrets Manager||データベースのユーザ情報等を管理するために利用|
|||KMS||データ領域暗号化のために利用|
|||GuardDuty||悪意のあるアクティビティがないかを確認し可視化と修復のために利用|
|||Inspector||ECRイメージに対して脆弱性スキャンを実施するために利用|
||認証・ユーザー管理|Cognito||ユーザー認証・認可サービス|
|||IAM||AWSのサービス・リソース利用にあたってのユーザ/サーバ権限を制御|
||監視・ログ|CloudWatch||AWSリソースとアプリケーションの監視|
|||CloudTrail||AWSのサービス・リソースに対する操作履歴を記録するために利用|
|||Config||AWSのサービス・リソースに対する設定変更履歴を記録するために利用|
||通知|SNS||CloudWatchにて検知した障害をメール送信機能にて通知するために利用|
|||Chatbot||CloudWatchにて検知した障害をSlackにて通知するために利用|
|||SES||メール通知のために利用|
||バックアップ|Backup||S3、Auroraのバックアップおよび災対環境へのコピーのために利用|
||自動化|EventBridge||定期的にバッチ処理を呼び出すために利用|
|||Step Functions||Lambda Functionの実行順序/ループ制御のために利用|

本システムの利用者及び接続要件は以下とする。

## 1.1.5 可用性・DR要件

| 項目名 | 内容 |
|--------|------|
| 目標稼働率 | 99.9%以上 |
| 災害対策構成 | プライマリ：東京、セカンダリ：大阪 |
| 復旧目標RPO | 1営業日前（日次バックアップ） |
| 復旧目標RTO | 0.5営業日以内 |

備考: 計画停止を除く24時間365日稼働を目標とする。Cross-Region Backup + 手動構築によるDR対策を実施。
