# インフラアーキテクチャ方針書

## オンライン処理方式

### 処理方式概要

| パターン | 採用するアーキテクチャ | 考慮事項 |
|------|------|------|
| フロント処理 | S3（静的WEBサイトホスティング）、CloudFront | S3で静的コンテンツ配信、CloudFrontでグローバル高速化・HTTPS対応。WAF連携で攻撃対策。|
| API処理 | Fargate、CloudFront | Fargateはサーバーレス運用・自動スケール。CloudFrontでAPI高速化。ALB・セキュリティグループ・WAF連携。APIによるDatabase更新。 |
| メール配信 | SES | SPF/DKIM/DMARC設定、バウンス・苦情率監視、送信制限・サンドボックス解除手順。|

### 実現イメージ

#### フロント処理

```mermaid
sequenceDiagram
    participant User as 利用者
    participant CF as CloudFront
    participant WAF as AWS WAF
    participant S3 as S3（静的WEBサイトホスティング）

    User->>CF: HTTPSリクエスト（Webページアクセス）
    CF->>WAF: セキュリティ検査
    WAF-->>CF: 検査結果
    alt キャッシュヒット
        CF-->>User: キャッシュからレスポンス返却
    else キャッシュミス
        CF->>S3: オリジンリクエスト（静的コンテンツ取得）
        S3-->>CF: 静的コンテンツ返却
        CF-->>User: オリジンからのレスポンス返却
    end
```

#### API処理

```mermaid
sequenceDiagram
    participant User as 利用者
    participant CF as CloudFront
    participant WAF as AWS WAF
    participant ALB as Application Load Balancer
    participant Fargate as Fargate（Web/APIシステム）

    User->>CF: HTTPSリクエスト（API/Webアクセス）
    CF->>WAF: セキュリティ検査
    WAF-->>CF: 検査結果
    CF->>ALB: オリジンリクエスト（API/Webリクエスト転送）
    ALB->>Fargate: リクエスト転送
    Fargate-->>ALB: レスポンス返却
    ALB-->>CF: レスポンス返却
    CF-->>User: キャッシュ or オリジンからのレスポンス返却
```

#### メール配信

```mermaid
sequenceDiagram
    participant App as アプリケーション
    participant SES as Amazon SES
    participant DNS as DNS Provider
    participant Recipient as 受信者

    App->>SES: メール送信リクエスト
    SES->>DNS: SPF/DKIM/DMARC検証
    DNS-->>SES: 検証結果
    SES->>SES: 送信者評価チェック
    alt 送信可能
        SES->>Recipient: メール配信
        Recipient-->>SES: 配信結果（成功/バウンス/苦情）
        SES-->>App: 配信ステータス通知
    else 送信制限・評価低下
        SES-->>App: 送信失敗通知
    end
```
