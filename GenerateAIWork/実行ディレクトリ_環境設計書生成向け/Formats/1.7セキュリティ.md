# 1.7 セキュリティ

## 1.7.1 サーバ対策

### (1)セキュリティパッチ適用

- システム構築時、OSについて最新のパッチレベルを適用する。\
- 運用開始後の適用については、[「２.運用設計」「２．１０．６　セキュリティパッチ適用」](./2.9障害児運用.md)を参照。

### (2)不要なサービスの停止

- サーバ機能の設計から必要なサービス抽出し、不要なサービスを停止する。

### (3) ウイルス対策・Webレビュテーション・ファイアウォール・侵入防御

- 本システムの本番/ステージング/開発環境Web/APサーバには、マルウェア対策/侵入防御を実施する。
上記要件より、以下の通り実装する。

|No.|製品名|環境|機能|対象|通知|通知先|補足事項|
|:-:|---|---|---|---|---|---|---|
|1|Trend Micro Cloud One|本番環境|不正プログラム対策|Web/AP Server|ON|JMAS運用チーム|動作：リアルタイムスキャン<br>検出時の動作：TrendMicroの推奨設定|
|2|Trend Micro Cloud One|本番環境|侵入防御|Web/AP Server|ON|JMAS運用チーム|動作：防御<br>侵入防御ルール：推奨設定を自動適用|

## 1.7.2 アカウント対策

### (1)アカウント設計

- AWS
  - AWSのルートアカウントは、JMASにて管理する。
  - AWSのIAMユーザは、利用者毎に作成する。
  - AWSのIAMユーザには、MFAを実装しなりすましを防止する。
  - AWS IAMグループで役割を定義し、IAMユーザはそのIAMグループに所属し、IAMポリシーを受け継ぐ。
  - IAMグループのポリシーとして、IPアクセス制限と特定のIAMロールへのスイッチを許可する。
    →当該IAMグループに所属するIAMユーザは、特定のIPアドレスからのみの、IAMロールへのスイッチしかできない。(AWSへのIPアドレス制限)
  - IAMロールとして、利用者用と管理者用の2つを作成する。
  - IAMロールのポリシーとして、利用者用と管理者用の2つを作成する。
- OS
  - システムはOS上にユーザを個別に作成しない。（デフォルトユーザのみ）
  - OSの操作はAmazon Systems ManagerのSession Manager機能を利用するため、OSを操作する権限はIAMユーザに統合される。
  - Systems Maganerでの接続および、セキュリティグループを操作する権限は、特定のIAMグループのみに制限する。
  - EC2のDefaultユーザは、パスワードにて接続する。
    →Defaultユーザパスワードはキーペアにて都度復号する。
  - Amazon Systems Managerでの接続が出来ない場合、セキュリティグループにてSSH(TCP:22)を最小限のIPアドレスから許可し、作成したOSユーザで接続する。
  また、Web/APサーバへSSH接続をする場合は、Bastionサーバ経由で実施する。
  必要な場合にのみ権限の与えられたユーザでのsudoコマンド作業を実施する。
- ミドルウェア
  - アプリベンダにて管理、設定する。
- RDS(Aurora含む)
  - DBAであるrootユーザとアプリケーション利用ユーザ、アプリケーション開発用ユーザを作成する。
  - 不要なアカウントは削除する。
  - アプリケーション利用ユーザ、アプリケーション開発用ユーザは、アプリケーションDBのみに対するフル権限を有する。
  - rootユーザは、最高権限ユーザである為、アプリケーションでは利用しない。

### (2)パスワードポリシー

以下要件をパスワードポリシーの原則とする。

- ８文字以上
- 少なくとも 1 つの大文字が必要
- 少なくとも 1 つの小文字が必要
- 少なくとも 1 つの数字が必要
- 少なくとも 1 つの英数字以外の文字が必要
- AWS
  上記のパスワードポリシーをAWS IAMのアカウント設定で制限する。
- OS
  OSユーザにはパスワードポリシーに従い設定する。
- ミドルウェア
  アプリベンダにて管理、設定する。
- RDS(Aurora含む)
  上記のパスワードポリシーを運用ルールにて設定する。

### (3)アクセス制御・ユーザ認証

- AWS
  - AWSのIAMユーザは、ユーザ名/パスワード/MFAでの認証とする。
  - 認証情報のローテーション/定期変更は実施しない。
  - AWS IAMポリシーにて、AWSマネジメントコンソールへのログイン後のアクションをIPアドレスにて制限する。
- OS
  OSユーザにはAWSより自動設定されるパスワードを使用する。
- ミドルウェア
  アプリベンダにて管理、設定する。
- RDS(Aurora含む)
  - ユーザ名/パスワードによる認証を行う。
  - hostの制限は行わず、セキュリティグループと併用する事で、接続元hostを制限する。

## 1.7.3 ログ取得・監査

ログ保存及び、監査用途の為、以下に記載のログを取得する。

### (1)AWS CloudTrail

AWS CloudTrail は、AWS アカウントのガバナンス、コンプライアンス、運用監査、リスク監査を行うためのサービスである。  
CloudTrail を使用すると、AWS インフラストラクチャ全体でアカウントアクティビティをログに記録し、継続的に監視し、保持できる。  
CloudTrail では、AWS マネジメントコンソール、AWS の SDK やコマンドラインツール、その他の AWS のサービスを使用して実行されるアクションなど、AWS アカウントアクティビティのイベント履歴を把握できる。  
このイベント履歴により、セキュリティ分析、リソース変更の追跡、トラブルシューティングをより簡単に実行可能となる。

|ログ|出力先|保存期間|保管期間超過時の浄化方法|浄化内容|
|---|---|---|---|---|
|全リージョンのCloudTrailログ|S3|1年|S3ライフサイクル|366日後に削除|

### (2)AWS Config

AWS Config は、AWS リソースの設定を評価、監査、審査できるサービスである。  
Config では、AWS リソースの設定が継続的にモニタリングおよび記録され、望まれる設定に対する記録された設定の評価を自動的に実行できる。  
Config を使用すると、AWS リソース間の設定や関連性の変更を確認し、詳細なリソース設定履歴を調べ、社内ガイドラインで指定された設定に対する全体的なコンプライアンスを確認できる。  
これにより、コンプライアンス監査、セキュリティ分析、変更管理、運用上のトラブルシューティングを簡素化できる。  

|ログ|出力先|保存期間|保管期間超過時の浄化方法|浄化内容|
|---|---|---|---|---|
|TokyoリージョンのConfigログ|S3|1年|AWS Configの標準機能|366日後に削除|

### (3)VPC Flow Logs

VPC フローログは、VPC のネットワークインターフェイスとの間で行き来する IP トラフィックに関する情報をキャプチャできるようにする機能である。  
フローログデータは Amazon CloudWatch Logs と Amazon S3 に発行できる。フローログを作成すると、選択した送信先でそのデータを取得して表示できる。  

|ログ|出力先|保存期間|保管期間超過時の浄化方法|浄化内容|
|---|---|---|---|---|
|使用VPCのトラフィックログ|S3|1年|S3ライフサイクル|366日後に削除|

### (4)ELB アクセスログ

ロードバランサーに送信されるリクエストについて、詳細情報を収集するアクセスログを提供。  
各ログには、リクエストを受け取った時刻、クライアントの IP アドレス、レイテンシー、リクエストのパス、サーバーレスポンスなどの情報が含まれる。  
これらのアクセスログを使用して、トラフィックパターンの分析や、問題のトラブルシューティングを行うことが可能。  

|ログ|出力先|保存期間|保管期間超過時の浄化方法|浄化内容|
|---|---|---|---|---|
|ELBのアクセスログ|S3|1年|S3ライフサイクル|366日後に削除|

### (5)Amazon Systems Manager Session Managerログ

Session Manager は、Systems Manager コンソールで現在のセッションと完了したセッションに関する情報を提供するだけでなく、  
AWS アカウントでのセッションアクティビティの監査とログ記録についてのオプションも提供。  

|ログ|出力先|保存期間|保管期間超過時の浄化方法|浄化内容|
|---|---|---|---|---|
|Session Managerでの操作履歴|S3|1年|S3ライフサイクル|366日後に削除|

### (6)AWS Lambda 実行ログ

Lambda は関数で処理されたすべてのリクエストをログに記録し、Amazon CloudWatch Logs ログを通じてコードで生成されたログを自動的に保存する。

## 1.7.4 データ対策

### (1)データ暗号化

- EC2のEBSボリュームは、機微情報を保持しない為暗号化を実施しない。
- S3Bucketはデフォルト暗号化を実施し、すべてのファイルを暗号化する。
- RDSのデータはAWS暗号化を実施する。

### (2)変更監視

- 変更監視は実施しない。

## 1.7.5 通信対策

### (1)通信の暗号化

- 原則、インターネットを通過する通信は、HTTPS/TLSで暗号化する。
- VPC内の通信に関しては、盗聴などのリスクが限りなく低いと判断し、コスト面の観点から暗号化通信を実施しない。

### (2)Webサーバ証明書

Webサーバ証明書を利用し、ELBまでの通信を暗号化する。
導入する証明書は以下の通り。

|No.|CNAME|取得元|期間|更新方法|利用環境|
|:-:|---|---|---|---|---|
|1|*.jmas.co.jp|Amazon Certificate Mangager|1年|DNS認証による自動更新|本番

### (3)侵入検知・防御

IPS/IDSのサーバや装置の設置は実施しない。
Trend Micro Cloud Oneが導入されているサーバに関しては、当該製品にて侵入防御・検知を実施する。

### (4)ファイアウォールの導入

- 別途ファイアウォール用途のサーバや装置の設置は実施しない。
- VPC内のリソースは、AWS VPCのセキュリティグループにて通信制御を行う。
- VPC外のリソースは、すべてAWS IAM認証による制限を行う。

### (5)DDoS対策の導入

- AWSでは、DDos対策として、AWS Shieldが標準で有効化されている。
- 本システムに採用する、AWS Shield Standardは、外部からの最も一般的なDDos攻撃に備える。
- Standardでは攻撃の検知やレポートは不可となっている。
